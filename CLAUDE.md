# Module 11 capstone — task-11.local

Local practice site only. **Never point any tooling (DevConnect, WP-CLI, Playwright) at a client site.**
The only allowed target is `http://task-11.local`.

## Tooling
- WP-CLI: `tools/wp.sh <command>` (wraps Local's PHP; DB on 127.0.0.1:10053).
- DB snapshot: `tools/snapshot.sh <label>` → `backups/NN-<label>.sql`. **Run before every destructive
  operation** (field-group changes, page rebuilds, content wipes, plugin/theme switches) and record it
  in `docs/issues-log.md` or the step's note.
- DevConnect bridge: MCP server `dev-command` (local scope) → `/wp-json/mcp/dev-connect-server`.
  Discover → inspect → dispatch. Credentials live only in the local Claude config, never in files.
  **Abilities with no arguments reject `{}`** ("input is not of type object", issue #6) → dispatch them with
  `{"_": 1}` instead, **but only when the schema has `additionalProperties: true`**. Otherwise pass a real
  optional parameter from `inspect-tool` (e.g. `dev/elementor-list-dynamic-tags` → `{"group": "..."}`).
- Elementor writes: native trees (`elType`/`elements`) go through `dev-connect/elementor-set-page-data` or
  `dev/elementor-create-theme-template`; `dev/build-page` takes DevConnect's canonical tree and silently drops native children
  (issue #15). After every tree write, count the stored nodes. Widgets use `_css_classes` (containers: `css_classes`).
  **Writes go through the MCP dispatch tool** (so DevCommand's QA ledger records them); `tools/bridge.sh` is for reads and
  oversized payloads only, and any write made with it is listed + verified in the step note (issue #16).
  Chrome trees are generated by `tools/elementor/build_chrome.py` (never hand-edit the JSON).
- Figma: REST API with `FIGMA_TOKEN` exported from `.secrets/figma-token` (gitignored). The Figma
  MCP connector hit its Starter-plan limit on task-9, so don't depend on it.

## Theme conventions (wp-content/themes/module11)
- Hello Elementor child. Every PHP function prefixed `m11_`; each concern in its own `inc/*.php`.
- **One layout = one template part + one SCSS partial**:
  `template-parts/flex-blocks/<layout>.php` + `assets/scss/layouts/_<layout>.scss` (`@use` it in `main.scss`).
- Flexible Content field `sections`; layout name `snake_case` → template part `kebab-case`.
- Inside FC use `get_sub_field()`. Escape all output (`esc_html`, `esc_url`, `esc_attr`, `wp_kses_post`).
  Images via `wp_get_attachment_image()` with `loading="lazy"` (not on the hero).
- **No `default_value` on ACF fields.** Every optional field must render cleanly when empty
  (wrap output in `if`), long headings must wrap, images use `object-fit` inside fixed-ratio boxes.
- Nothing visible is hardcoded in templates — content comes from fields; site-wide values
  (logo, phone, email, address, socials, brand colours, fonts) come from Site Settings (`m11_get_setting()`).
- Colours only via `var(--clr-*)`; type via `fluid-font()`; breakpoints via `minmedia()`/`maxmedia()`.
- ACF Local JSON saves to `acf-json/` and **is committed** with every field change. **Author field groups as Local JSON files**
  (stable keys `group_m11_*` / `field_m11*`). Never create or update them with `dev/acf-manage-field-groups`: it silently drops
  fields and FC layouts (issue #12). Use that ability only for read-back verification.
- Build CSS: `cd wp-content/themes/module11 && npm run build`.

## Working method
- Work one step at a time; confirm with the developer before moving to the next stage.
- Verify every change (front end at 1440/768/390, plus wp-admin editability) before calling it done.
- **Whenever the tooling or conversion gets something wrong, log it in `docs/issues-log.md`**:
  symptom → how it was noticed → root cause → fix/patch → how it was verified. This is assessed.
- Evidence (screenshots, generated HTML, conversion output) goes under `docs/evidence/<area>/`.
- At the end of every step, update `docs/BUILD-NOTES.md` (readable summary: issues + fixes + builder reasoning), keeping
  its numbering in sync with `docs/issues-log.md`.
- Builder split (decided): About Us + Contact Us = Elementor; Home, Products (CPT + archive), Resources, Sales Hub = ACF;
  header/footer = Elementor Theme Builder; colours/fonts = Elementor Kit; business data = ACF Site Settings.
